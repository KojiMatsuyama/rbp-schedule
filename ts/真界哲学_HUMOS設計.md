## 本質（哲学）— 真界の正体

> **真界は、記号界と物理界が、もたれかかりによって交互に運動し、理と実働がトラストの中でブリッジされ、未来永劫のドミノとして自己持続する系である。**

> **要約（真骨頂）**: 真界哲学は、lean 哲学であって、その真骨頂は、従来の哲学が越えられなかった
> 記号界と物理界を統合した統合世界として哲学的に定義可能にしたことである。それは、「理＝ロゴス」に
> 汎用をも持たせる元素と意味のある順序セットを発見したことで、はじめて、両界を跨る統合世界を
> 人間が出現させることに成功したことである。

この文書は**二層**を持つ。上の「本質（哲学）」は**純粋な哲学**（経営哲学ではない）、
下の §1〜§8 はその哲学を**経営工学にスポットを当てた実装（HUMOS）**である。

- **真界（TW）＝純粋な哲学** — 人という**知能生命**が、脳の中の記号と身体が接した物理界に
  存在し、**身体を通じて物理界を記号化して認知**し、脳で記号論により行動の成功率を最大化する
  **評価**と物理制約の**決定**を行う——これが**トラスト形成**であり、あとはその確率にかけて
  物理界で身体を行動させている、という純粋な哲学。
- **HUMOS ＝ その哲学の実装** — しかも人と機械の実働という**経営工学**にスポットを当てた実装。
  それ以外のサイバネティクス的な実装まで一般化できているかは正直未確定。
  「HUMOS 設計は、現在のところ、この真界哲学を経営工学に応用して設計実装しているに過ぎない。」

### もたれかかり（受動的能動の芯）

真界の特徴的な哲学は**受動的能動**——言い換えれば**もたれかかり**。前のドミノがもたれかかるので、
次のドミノの受動的能動運動が連動する。これは**力でもなく、重力（引く力）でもなく、意思（意志）でもない**
（接触と傾き）。**オキシモロン**であり**一息で読む**ことでしか成立しない——分解・定義すると意味が
成立しない（禅の「不立文字」・道家と同型の、読みという**時間の中で成立する現象論**）。
故に WHAT／HOW に分解しない。一行（ポインタ）として据える。

### 交互（抱合でも還元でもない）

二つの界は**非連続**であり**決して交わらない**（混ざって連続になるのではない）。一つになるのは
**交互**によって: 記号界物理界記号界物理界記号界物理界……。これは**抱合（全体論）ではない**。
**還元論**ではある（世界は元素に還元される）が**還元論だけではない**——その元素が重力で運動し、
その状態が過去から未来永劫続いている。二界が一つになるのは、同じ元素・重力・順序構造を共有しているから。

### 二重性 — ネットワーク構造と統合された世界

真界は**構造的には**「記号界物理界記号界物理界」と**相互連作するネットワーク構造**をしている。しかし
記号界と物理界を**ひと塊に、真界という世界として統合定義**した。ゆえに真界は**二重性**を持つ
（構造＝相互連作のネットワーク ／ 定義＝統合された一つの世界）。**TrueNet → TrueWorld 改名の意図**は、
構造の名称（ネットワーク構造）を変えるためでなく、**真界哲学を簡素にする**ためである。構造は依然
ネットワークのまま、「世界」と呼ぶことで統合定義（二重性の定義側）を簡素に表す。

### 5 元素 ＝ 汎用的な「理」の元素順序セット（トラスト元素）

**認知 → 評価 → 決定 → 投射 → 作動** は、汎用的な**「理」の元素順序セット**として構造化されたもの。
交わらない二界を渡る元素と順序。状態が揃うと**自動発火**し、記号界でトラストが形成され、
二界を橋渡しし、**実働にジャンプ**する。この構造化が、トラスト形成を**はじめて汎用的に**
実現できた所以。

### 理 ＝ 順 ＝ 運動の帰結（法則ではない）

自動運動はロゴス＝理性でもなく、タオでもない。「理」というなら**「順」（順序・並び）**にあたる。
理は運動を治める**法則**ではなく、運動の**帰結**——元素と並び（順）が**すべての「理」を構成**している。
方向は逆: 「法則が運動を治める」でなく「**運動が法則を構成する**」。核心の語は**自動無限運動**
（ボートは後ろ向きにこぐ＝過去のデータ・記号界の投射へ、一方で未来にスパークする＝物理界の抵抗へ）。

### 重力の発生 ＝ M0（最初の押し）

誰がドミノを並べ、誰が最初のドミノを倒したのか——それは**重力の発生**＝**M0（初期マーキング）**。
それ以後、系は自ら動く（受動的能動）。

### 理と実働のブリッジ（送り込みの成功）

理（記号界）と実働（物理界）は、トラストの中で**もたれかかりのエネルギー**によりブリッジされ、
**送り込みが成功**する。哲学的主張に留まらず**実装**（STN・発火ループ・帰還）として成立している。

### 未来永劫のドミノ・生命の現象論

ネットのようにつながって物理界の状態を遷移させ、状態記号が記号界へ還り、物理界の状態変化が整うと、
次のトラスト形成が記号界で自動的に形成され、また物理界にジャンプする。**真界は生命の現象論**——
非連続・決して交わらない二界を、生命がトラストを形成しながら果敢に生きていく。

### 実現の力学（境界の力学）

真界の実現範囲は固定ではない。記号化・接続のカバー率で伸び縮みする。

> 真界哲学を実世界での実現を促すのは、物理界のあらゆる人モノコトをオブジェクトして記号化すること。そして、あらゆるものをネットにつなぐことである。逆にいえば、記号界に登録しないこと、そして、ネットにつなげないこと、あるいは、オフネットすることで、真界哲学の実現を遅らせることができる。

**実現の境界 ＝ 記号化され、かつネットに接続された対象の集合。**

- **促す（拡張）：** 物理界のあらゆる人・物・事をオブジェクトして記号化 ＋ あらゆるものをネットにつなぐ。
- **遅らせる（収縮）：** 記号界に登録しない ＋ ネットにつなげない ＋ オフネット。

### 真界哲学の意味 — 認知のスパーク現象

> 真界哲学の意味は、これまでの認知論＝記号界から物理界の接続ができないという発見で止まっていた。その哲学真理は間違いない。しかし、現実は、生命は物理界で生きている。これを、「ボートを未来に向かって後ろ向きに漕いでいる」とヴァレラが表現した。これは、「ロゴス」「理」が、知の中核であって、汎用性のある再現可能なフレームが発見されていなかったからである。真界哲学は、この「ロゴス」「理」の生成にかかわる元素と順序セットを発見し「トラスト形成」という概念化し、ブラックボックスであった、「認知のスパーク現象」を人間が扱える哲学モデルにしたことである。これによって、予め記号界から物理界への接続を設計できるようになったことは、記号界と物理界を統合して人間が扱える意味がある。そして、それは、記号界から、物理界の調和を設計できる可能性を生み出したという疑義がある。

- **従来の認知論の到達点。** 記号界から物理界への**接続ができない**、という発見で止まっていた。その真理は正しい。
- **しかし現実は、生命は物理界で生きている。** ヴァレラの「ボートを後ろ向きに漕ぎ進める未来へのスパーク現象」。
- **原因。** 「ロゴス」「理」は知の中核だが、**汎用性のある再現可能なフレームが未発見**だった。
- **真界哲学の貢献。** 「ロゴス」「理」の**生成**に関わる元素と順序セットを発見し「**トラスト形成**」と概念化し、
  ブラックボックスだった「**認知のスパーク現象**」を、人間が扱える哲学モデルにした。
- **帰結。** 記号界→物理界の接続を**予め設計**できるようになった ＝ 二界を統合して人間が扱える。
- **疑義（保留）。** 記号界から**物理界の調和を設計できる可能性**を生み出した。単なる利点でなく、問いとして。

### 真界哲学の説明 — lean 哲学

真界哲学は、lean 哲学である。受動的能動が無限運動の力学になっている。ヴァレラなど認知哲学派ともいえる、
過去を見ながら未来に後ろ向きにボートを漕ぐようなものだというのは、まさに、認知哲学が、未来へどのようにつながって
いっているのかが闇のままで止まっている。lean 哲学があっても、ベルグソンがどれだけ自動運動を提唱しても、
ストア派のロゴス、宋期の「理学」が、論理の向こう側にどうしても渡れないでいる。それは、「理」が個別だから
哲学にならないので、哲学の行き止まりなのである。「理」の一般系は、個別な理の汎化ではない、微細化である。
「理」の構成元素と理として働く順序が必要だったのである。「認知ー評価ー決定ー投射ー作動」という 5 元素の
順列セットでどのような「理」も構成できることの発見が、真界哲学の真理である。これは、真界哲学では、トラスト
形成と呼ばれる、いわゆる、記号界と物理界を渡す「理の橋」を出現させるのである。理の橋＝ロジックブリッジ、
すなわちストア派のロゴスが、認知と実世界にロゴスブリッジを出現させるのである。これによって、あらゆる哲学が
ようやく動き出す。ホワイトヘッドが唱えた記号界と物理界を相互に連鎖する、過去から未来へと連鎖する出来事の

## 1. 本質（4層）— 実装層（HUMOS）

> 上の「本質（哲学）」が**純粋な哲学**（真界の正体）であるのに対し、この §1〜§8 は
> その哲学を**経営工学にスポットを当てた実装（HUMOS）**の純化である。

真界哲学と HUMOS 設計は 4 層に純化する。上から「何であるか」→「核心」→「機構」→「OS である所以」。

### 1.1 本質 — 相互に開かれた状態系

**記号界と物理界が相互に開かれた状態系。**

二分解（§2）は「何から成るか」だが、本質は二つの界が**相互に開かれている**ことである。
一方だけが閉じていれば真界ではない。相互開きにより、記号界の判断が物理界へ届き（作動）、
物理界の実働が記号界へ還る（感覚）ことで、一つの閉じた状態系となる。
相互開きと自動発火が系を自己駆動させる——これは帰結する**性質**であり、本質そのものではない。

### 1.2 深層の核心 — トラスト形成（trust formation）

HUMOS を実働 OS たらしめる核心は、ネット構造（STN）ではなく、**判断の汎用化**である。
要求（確率）と仕様（決定）の一塊を、手続きではなく**原子化**した 4 元素で構成する:

```
認知 → 評価 → 決定 → 投射
```

- **確率（記号界）** — 記号界で計算できる統計的な確率（RBP 鏡像 ID・コサイン類似度）。
- **決定（物理界の実情）** — 物理的な制約（実情）の中で決定（在庫>0 等のブリッジ）。
- **確率 → 決定** のプロセスを **トラスト形成** と名付ける。
- この 4 元素の**組み合わせ**で、意思決定を**汎用化・機械化（自動化）**する。
  これが「実働におけるトラスト形成」すなわち**意思決定の機械化**である。

STN はこの判断を載せる**構造（土台）**にすぎない。核心は判断エンジン（4 元素）側にある。

**判断は二速度で走る（反射と審議）** — 4 元素（認知→評価→決定→投射）は**審議**（遅い・中央経路）の
経路であり、LLM・Haskell・DB 単一化が乗る高価な判断だ。だが常態は審議を要しない。
在庫が在手なら、天気が良ければ、散布が完了すれば——ネットは**反射**（速い・局部）で次トランジションを
発火して再開する（`enabled_when` の宣言的発火・cron・在庫結果での再開）。
**常態の帰還は反射で再開し、例外の帰還（欠品・天不良・突然の病害）だけ審議にエスカレートする。**
高価な脳を常態で回し続けない——これが判断の汎用化（意思決定の機械化）を安価に保つ理由である
（[TS概念.md §5](TS概念.md)）。

### 1.3 機構（mechanism）

本質と核心を実現する具体機構:

| 機構 | 役割 |
|---|---|
| **SSS** 空間状態システム | 状態空間の**土壌**。一般システム理論を思想にもち、状態認識・**状態予測**（カルマンフィルタ予定）・通知 |
| **STN** 状態遷移ネット | **構造**（P＋T）。ペトリの原形を残し、物理界に開く |
| **発火ループ**（VM） | STN の**実行機構**。マーキング駆動の enabled→fire→loop。どのネットでも同じ不変の**ペトリネット仮想マシン**（ネット構造＝プログラム、発火ループ＝VM） |
| **RBP** 境界言語 | **トラスト形成エンジン**（オリジナル）。処理系から**意味を排除**する＝「オート」。境界言語は人間系↔機械系の翻訳者（要求仕様定義） |
| **SOS** 作動の運動器 | 作動（記号界で実働できるシステムの操作） |
| **接地** | 未接地の系は真界（TrueWorld）ではない |
| **ドメインオブジェクト** | 圃場（状態保持）・コホート（遷移のまとまり・階層）・実行者（作動・人/機械/ロボット/SOS）— §3.7 |

### 1.4 OS である所以

**汎用化（エンジン不変・ナレッジは可変データ）→ 意思決定の機械化（自動化）。**

判断エンジン（4 元素）と機構（SSS/STN/RBP/SOS）は**ドメインに依存しない不変のエンジン**であり、
各業務・各ドメインの知識（緒言）は**データ**として差し替える。この分離により、
STB・DC・将来の任意のドメインで**同一の OS** が成立する。

この不変のエンジンは 3 つの柱で運用される（[真界_実装状況.md](真界_実装状況.md) の「第3の柱 PLAN」）:

- **実行（発火ループ / VM）** — 不変の VM が可変のネット構造を解釈し、系を自己駆動させる。
- **状態（SSS）** — 書き込みを空間状態として認識・予測・通知し、**実状態 Actual State(T)** を保持する。
- **運用（PLAN）** — **期待状態 Expected State(T)** の正（業務定義 DB）。状態の柱を**期待状態の次元で拡張**するレイヤー
  （[運航管理センターUI設計.md](運航管理センターUI設計.md)）。
  **異常 ＝ Expected State(T) ≠ Actual State(T)**。
  実状態（SSS）と期待状態（PLAN）を突き合わせて、逸脱（on_track / deviating / overdue）を判定する。

3 柱は全て**ドメイン不変のエンジン**であり、ドメイン依存するのはネット構造とナレッジ（緒言）だけ。
この「不変の 3 柱 ＋ 可変のナレッジ」の分離が、OS である所以である。

## 2. 真界（TW）の構成 — 二分解

```
真界 (TrueWorld / TW)
│
├─ 記号界 (SymbolWorld)
│  │
│  ├─ HUMOS（土壌 / 状態空間管理基盤）
│  │  ├─ SSS  空間状態システム (Spatial State System)
│  │  │        書き込みを「空間状態」として認識・予測・通知
│  │  │        認知スコープ: STN ＋ 物理界の実働（オペレータ）
│  │  │
│  │  └─ STN  状態遷移ネット (State Transition Net)
│  │           ＝ P（プレース）＋ T（トランジション）
│  │           T ＝ { 認知, 評価, 決定, 投射 } ＋ 作動
│  │
│  ├─ IF   膜（感覚・運動・ポートの集合）
│  │        感覚: 物理界 → HUMOS ／ 運動: HUMOS → 物理界
│  │
│  └─ SOS  作動の運動器（Slack送信など、記号界で実働できるシステムを操作）
│
└─ 物理界 (PhysicalWorld)
   ├─ 実働（オペレータ）: 人・機械・ロボット・業務アプリ・物
   └─ ドメインオブジェクト（状態の保持体）: 圃場・コホート・実行者
        圃場＝状態保持(期+フェーズ)／コホート＝状態遷移のまとまり(階層)／実行者＝状態遷移の作動
```

**真界 ＝ 記号界 ＋ 物理界**
**記号界 ＝ HUMOS（SSS ＋ STN）＋ IF ＋ SOS**
**物理界 ＝ 実働（オペレータ）＋ ドメインオブジェクト（状態の保持体）**

> 記号界（STN）が管理するのは**遷移**であり、**状態**を保持するのは物理界の
> **ドメインオブジェクト**である（§3.7）。この分離が接地を一段深くする。

「未接地の系は真界ではない」の TW。TS（システム名）と TW（世界名）は同一の閉じた系。

## 3. 機構の詳細

### 3.1 SSS — 空間状態システム（土壌）

HUMOS の本質。書き込み（マーキング・トランジション発火ログ・モジュールログ・SOS 作動ログ）を
**空間状態として認識**し、一般システム理論で**状態認識・状態予測・通知**する。
認知スコープは STN に留まらず、物理界の実働（オペレータ）も対象。
状態予測は**カルマンフィルタ**を実装して補う（予定）。

- **状態認識** — 書き込みの集合を、今の空間状態 M として認識する
- **状態予測** — 一般システム理論で状態の遷移を予測する（カルマンフィルタ予定）
- **通知** — 状態変化をリアルタイムに通知する

> **圃場状態は空間状態の入口**（石4）。圃場が保持する「どの期の苗・どのフェーズ」
> が SSS の空間状態 M の第一の具体である（§3.7）。

### 3.2 STN — 状態遷移ネット（構造）

```
STN ＝ P（プレース）＋ T（トランジション）
T ＝ { 認知, 評価, 決定, 投射 } ＋ 作動
```

- **P（プレース）** — トークン集約・境界。値は HUMOS のマーキング（ライブ M）。
- **T（トランジション）** — 各 T は発火時に 認知→評価→決定→投射（記号的処理）を
  **内部で**走り、最終到達点の**作動（物理界的作動）**に到達する。作動が T の正体。
  これは T の分類でなく、**全 T に共通する T の内部構造（発火のセマンティクス）**。
  各業務トランジション（薬剤選定・在庫チェック・防除実施・検鏡・定植…）は、
  この普遍構造をその業務で**具現化（パラメータ化）**したものである。
- **能動ゲート** — 発火判定 `enabled_when` は「上流が発火したか」でなく、
  **HUMOS のライブマーキング（今このプレースにトークンがあるか）を読む**。
- **純粋ペトリネットのまま** — STN は IF・SOS を直接 import しない。
  読む・書くのは HUMOS のマーキングとイベントだけ（間接的開き、§4）。
- **正（source of truth）** — [jobnet.py](../jobnet.py)（NET dict）。

### 3.2.1 発火ループ — ペトリネットの仮想マシン（VM）

STN を動かす実行機構。マーキング駆動のループで、**どのネットでも同じ不変のコード**である。

```
M = M0（初期マーキング）
loop:
    enabled = [t for t in T if is_enabled(t, M)]   # HUMOS のライブマーキングを読む（能動ゲート）
    if not enabled: break                            # 固定点＝停止
    step = maximal_non_conflicting(enabled)
    M = fire(step, M)                                # 消費→生成→マーキング更新（HUMOS 書き込み）
```

| | プログラム（データ） | インタープリター（コード） |
|---|---|---|
| 何 | ネット構造（P, T, F, M0） | 発火ループ（VM） |
| 変わるか | 業務ロジックが変わると変わる（可変データ） | 変わらない（不変） |

- **構造（プログラム）と解釈（VM）の分離** — 発火ループは「設計する」のでなく、
  ペトリネットの定義から決まる**オペレーションセマンティクスそのもの**を実装する。
  一度書いて終わり。業務が変わっても VM は変わらない。
- **停止・再開は別機構でなく、このループの帰結** — `external_wait` 到達で enabled な T が
  なくなり固定点（停止）、外部イベントがトークンを置けば再評価で再開（§5）。
- **これが「OS である所以」の実体** — 不変の VM ＋ 可変のネット構造・ナレッジ（§1.4）。
  （[TS設計.md §11.6〜§11.12](TS設計.md)）

### 3.3 RBP — トラスト形成エンジン（境界言語）

深層の核心（§1.2）を実装するエンジン。既存の形式体系に由来しない**オリジナル**の発想軸。

- **処理系から意味を排除する＝「オート」** — 判断を意味（解釈）でなく、
  行列（鏡像 ID・コサイン類似度＝確率）とブリッジ（在庫>0 等＝決定）で機械化する。
  処理系に意味が入ると「オート」が破れる。意味は境界言語の翻訳に委ねる。
- **境界言語＝人間系↔機械系の翻訳者** — 要求仕様を境界言語で定義し、
  RBP 行列（要求評価・仕様決定）は**自動導出**される。人間は行列を設計しない。
- **確率 → 決定** — 鏡像 ID（確率）で要求を測り、ブリッジ（物理的制約）で決定する。
  これがトラスト形成の機械化であり、意思決定の原子化（4 元素）の実体。

### 3.4 SOS — 作動の運動器

記号界で実働できるシステムを操作するライブラリ（Slack 送信など）。
HUMOS の内側・IF の内側に座る（独立した第 4 層でなく、SSS が発する作動指示を実行する部品）。

### 3.5 IF — 膜（感覚・運動）

境界（membrane）。ポートの集合。

- **感覚（入力）**: 物理界の実働状態を HUMOS に取り入れる。
- **運動（出力）**: HUMOS の作動指示を物理界へ届ける。
- **IF 契約** — 「物理世界が種別 K のトークンをプレース P に制約 C 内で返す」ことの宣言。
  宣言・アダプタ・コードは全て記号界の産物なので、膜は**記号界の構成要素**。
  宣言しなければ作動は**漏れ**（出はするが戻らない）で、系は閉じない。

### 3.6 接地

物理界は「入力ポート」でなく、**空間状態を変えるオペレータ**として SSS に認知される。
これが接地の具体。**未接地の系は真界（TrueWorld）ではない。**

### 3.7 ドメインオブジェクト（状態の保持体）

STN が管理するのは**遷移**であり、**状態**を保持するのは物理界の
ドメインオブジェクトである。これは §3.6 の接地を一段深くする。

> **ネットと呼ぶのは STN（状態遷移ネット）だけである。**
> 真界（TrueWorld）は世界（閉じた系）でありネットではない。ドメインオブジェクトもネットではない。圃場はネットを持たない。
> 育苗圃が「第5期育苗を栽培中」という状態を持つのは、そのオブジェクトが
> 状態属性を保持しているからであり、STN のどこかにその状態があるわけでは
> ない。STN のトランジションがその状態を**変える**。

**圃場**は状態保持の代表例。育苗圃・本圃 は共に「圃場」型（温室ではない）。

| 圃場 | 設備 | 保持できる状態 |
|---|---|---|
| 育苗圃 | 育苗用ベッド・育苗棚（定植用ベッドなし） | 空／第N期育苗(栽培中)／定植完了(片づけ未完了)／空 |
| 本圃 | 定植用ベッド | 空／第N期定植苗(栽培中)／… |

圃場は**同期の苗のみ**保持し、混合保持しない。圃場状態は二値でなく
**ライフサイクル**である：

```
空 → 第N期育苗(栽培中) → 定植完了(片づけ未完了) → 空
```

「定植完了(片づけ未完了)」は、定植は終わったが育苗苗の片づけが未完了という
中間状態。圃場状態の確定は**ハイブリッド遷移**である：STN のイベント駆動
（定植完了）と人間の確認駆動（圃場責任者（実行者）への Yes/No）の両方で
確定する（§3.4）。

**コホート**は状態遷移のまとまりであり、階層を持つ。

```
第5期 (ルート)
 └─ 圃場 (中間)
     └─ トランジション (葉)
```

3 層：第5期（ルート）→ 圃場（中間）→ トランジション（葉）。圃場は状態
保持体であり、STN のノードそのものではない。STN が遷移を管理する。

**コホートの表示は解像度で決める**（UI 階層解像）。トップレベルでは
コホートの 1 階層子のみをマクロノードとして表示し、より深い階層は折り畳む。

```
検鏡[育苗圃] → 定植[ブリッジ] → 防除[本圃] → 収穫[本圃]
```

解像度を上げる（プルダウンで検鏡/定植/防除を選択）と、そのマクロが展開
される。これは階層ペトリネット／マクロ展開であり、ネット合成（マクロ化＋
ブリッジパターン）の実装である。

**要求トークン ＝ オブジェクト × スケジュール**。要求は必ずプレースに接続
される（§5、真界_オブジェクト接地設計.md §4.1）。トークンは要求種別ごとに
**属性のサブセット**を運ぶ：

| 要求種別 | トークンが運ぶ属性 |
|---|---|
| 定植要求 | 圃場、beds |
| 防除要求 | 圃場、面積、which:N |
| 検鏡要求 | 圃場、保持中:第N期育苗、which:検鏡N |

「面積」は圃場の属性だが、防除要求の場合のみトークンに載る（薬液量＝
面積×希釈率の判断に必要）。育苗圃でも本圃でも同じ。

**防除は反復であり、検鏡は連鎖である。**

- **防除**：同じ episode の反復（毎回 認知→評価→決定→投射→作動 の全 5 段）。
  N 個のコホートを手作りするのではなく、**1 つの防除マクロ**を作り、トークン
  からインスタンスを生成する（防除暦の値＝N）。
- **検鏡**：異なる段の連鎖（検鏡1→…→検鏡N→定植）。

**検鏡要求は条件付き**である。育苗圃は「自分が現在保持している第5期育苗を
検鏡して」という要求を発生させる。これは圃場が内部状態から発生させる
**内部状態遷移型**であり、那賀連合会の分化あり/なし判定（P_external_wait、
**外部観測型**）とは区別される。

**実働＝状態遷移の作動**。圃場状態のデジタル化は物理界の実働（人）が
担う。オブジェクトは1種類で、役割（実行者）で差別化する（[真界_事業主体設計.md §2.3](真界_事業主体設計.md)）。

- **育苗責任者**（実行者）：定植完了と同時に育苗圃の状態更新を従業員 Slack
  に送信。Yes/No を選べる文面。育苗責任者が「Yes」を選ぶと、育苗圃の保持苗状態を
  「空」に変更（実働の作動）。
- 「No」を選ぶと「定植は終わっている。育苗苗の片づけが未完了」。
- **圃場責任者**（実行者）は各圃場に個別に確認する。
- 実行者は登場するごとにドメインにオブジェクト（人）として登録され、主体から
  委任（雇用・実行者）される。

実働は石3（在庫リフレックス：write_sos → Slack → 人間 → 状態更新）
の役割名であり、状態遷移の作動（T の正体）である。
> **2026-09-14**: 「エージェント」概念は廃止（[真界_事業主体設計.md §2.1](真界_事業主体設計.md)）。
> 化身＝接地、実行者＝実働、で吸収。

## 4. 設計の核心 — 間接的開き

> **STN は直接に物理界を触らない。必ず HUMOS を介す。**

- STN は純粋ペトリネットのまま（検証可能性を保持）。
- HUMOS が記号界と物理界の**両界に開いた状態空間**として問題を管理する。
- STN は HUMOS からイベントを受け取り、間接的に物理界に開く。
- 直接に開くと純粋さが失われる（検証不能）。間接的に開くと、純粋さと接地を両立する。

**間接性が、閉包と接地を両立させる。**

## 5. 二つの流

```
入力流（感覚）
  物理界（実働）─IF─▶ HUMOS ─イベント─▶ STN（要求プレースに要求トークンを置く → マーキング駆動で発火）

出力流（作動）
  STN（作動T発火）─▶ HUMOS ─▶ SOS ─▶ IF ─▶ 物理界（実働）
  物理界（実働完了）─IF─▶ HUMOS（作動完了ログ・状態判断）─▶ STN（次トランジション自動発火）
```

- **入力は必ずプレースに接続される（トランジションには直接接続しない）** —
  入力流（感覚）が STN に届く先は、対象トランジションの**一つ前のプレース**（要求プレース）
  であり、そこに**要求トークン**を置く。トランジションは要求を**読む**側で、
  要求の**着地点**ではない。要求がプレース（マーキング）に置かれることで、
  マーキング駆動発火ループ（石2）が「要求＋他条件が揃ったら発火」を自然に判定する
  （不変条件 5「マーキング ≡ M0 からのリプレイ」）。
  詳細は [真界_オブジェクト接地設計.md §4.1](真界_オブジェクト接地設計.md)。
- **SOS 作動の完了が状態である** — Slack送信した、は副作用でなく HUMOS の状態。
  HUMOS が記録→状態判断→次トークンを置く→STN が自動発火する（在庫リフレックス）。
- **イベントは彩色**（識別子＋ペイロード）。個数でなく内容を運ぶ。
- **停止・再開はマーキング駆動ループの帰結** — 外部待ち（`external_wait`）で
  enabled な T がなくなれば停止（固定点）、外部イベントがトークンを置けば再開。
  停止・再開は別機構でなく、ループの自然な帰結。

## 6. 不変条件（TW が TW である条件）

1. **未接地の系は真界（TrueWorld）ではない。** ネットと呼ぶのは STN だけ。
2. **STN は IF・SOS を直接 import しない。** 読む・書くのは HUMOS のマーキングとイベントだけ。
3. **物理界との接触点は HUMOS に一点に集約する。** 別経路で物理界を触るコードは閉包違反。
4. **物理界の全状態変化に IF ポートがある。** 制御できない入力もポートとして列挙する。
5. **HUMOS のマーキング ≡ M0 からのリプレイ。** 内部整合は機械的に検証できる。
6. **状態はドメインオブジェクトが保持し、STN は遷移を管理する。** 圃場が「第N期育苗を栽培中」
   と持つのはオブジェクトの状態属性であり、STN のどこかにその状態があるのではない。
   STN のトランジションがその状態を変える（§3.7）。ネットと呼ぶのは STN だけ（真界は世界）。

（接地・閉包・有界性の詳細は [TS概念.md §3](TS概念.md)）

## 7. 漸増的ライフサイクル — 生き続ける系（living system）

普遍構造（T ＝ { 認知, 評価, 決定, 投射 } ＋ 作動、作動が T の正体）は**骨格**。
各 T が真の T（接地）になるには、その T 固有の**ナレッジ（RBP）**を埋める。
骨格だけ（ナレッジ未実装）の T は**写生（スケッチ）**であり、まだ真の T ではない。

- **判断{認知・評価・決定・投射}は不変** — 要求と仕様のナレッジで形成
  （要求評価 RBP 行列と仕様決定 RBP 行列を境界言語で定義・生成）。
- **全 T に最終的にはナレッジ（RBP）の実装が必要** — 骨格は共通、ナレッジは T ごとに異なる。
- **漸増的デザイン・実装** — 業務をコホートごとに部分部分で写生し、描画しながら全体に近づく。
- **稼働は別フェーズ（完全性のゲート）** — 一連に接地（全 T がナレッジ＋作動を備える）した
  ときのみ稼働。不完全なネットは未接地（不変条件 1）で真界（TrueWorld）ではない。
- **稼働後の漸増的保守運用** — 稼働後も T の増減・ナレッジの変化が続く。保守運用が稼働と一体。
  STN 構造とナレッジは**共に可変データ**として自己進化し、閉じた接地系を保つ。発火ループ（VM）は不変。
- **ナレッジ設計の設計方法論** — 1 つの T のナレッジは**作動（物理界的作動・T の正体）に
  アンカーを固定**し、投射→仕様決定→評価→認知と一段ずつ戻って設計する。各段の**緒言
  （資材・手順・データ）を DB に登録**し、**RBP 行列は境界言語で自動導出**する（人間は
  行列を設計しない）。要求発生状態は外部観測型（病害虫 DB）か内部状態遷移型（マーキング＋マスター）。

（詳細は [TS設計.md §12](TS設計.md)、特に §12.7 ナレッジ設計の設計方法論）

## 8. 用語表

| 語 | 定義 |
|---|---|
| **真界**（TrueWorld / **TW**） | 記号界と物理界が相互に開かれた閉じた状態系（世界）。ネットではない（STN がネット）。**純粋な哲学**（経営哲学でない） |
| **真界の正体** | 記号界と物理界がもたれかかりで交互に運動し、理と実働がトラストの中でブリッジされ、未来永劫のドミノとして自己持続する系（本質（哲学）） |
| **受動的能動／もたれかかり** | 真界の芯。前のドミノがもたれかかり次のドミノが連動。力でも重力でも意思でもない。オキシモロン・一息で読む（分解不可） |
| **交互** | 非連続・決して交わらない二界が一つになる方式（記号界物理界記号界…）。抱合（全体論）でも還元でもない |
| **トラスト元素** | 認知→評価→決定→投射→作動。交わらない二界を渡る汎用的な「理」の元素順序セット。状態が揃うと自動発火し実働にジャンプ |
| **理＝順** | 理は法則でなく運動の帰結（元素と並びがすべての理を構成）。方向は「運動が法則を構成する」 |
| **自動無限運動** | ボートが後ろ向きにこぎ（記号界の投射）ながら未来にスパーク（物理界の抵抗）し続ける核心の語 |
| **重力の発生（M0）** | 誰がドミノを並べ最初のドミノを倒したか＝初期マーキング M0。以後系は自ら動く |
| **未来永劫のドミノ** | トラスト形成→実働→帰還→次のトラスト形成がネットワークのようにつながり自己持続。真界＝生命の現象論 |
| **実現の力学（境界の力学）** | 実現の境界＝記号化され、かつネットに接続された対象の集合。記号化＋接続で拡張、未登録・オフネットで収縮（可逆・動的） |
| **認知のスパーク現象** | 記号界→物理界を飛躍させる「スパーク」。ブラックボックスだったものを「トラスト形成」で扱える哲学モデルにした |
| **物理界の調和の設計** | 記号界から物理界の調和を設計できる**可能性**。疑義として保留 |
| **学派（一派）** | 名はポインタ（真界一派・未確定）。芯＝受動的能動・もたれかかり（一息・不固定） |
| **world**（世界） | HUMOS の最上位概念＝閉じた系（デプロイ/インスタンス）。`world_id`。ドメインは world に内包。STB=`stb`、DC=`dc`（§2・[真界_事業主体設計.md §4](真界_事業主体設計.md)） |
| **本質（実装層）** | 相互に開かれた状態系（§1.1）。哲学層の実装への投影 |
| **トラスト形成** | 確率（記号界・統計）→決定（物理制約・実情）を 4 元素に原子化＝意思決定の機械化（§1.2） |
| **HUMOS** | 土壌（状態空間管理基盤）。SSS＋STN を含む |
| **SSS** 空間状態システム | 状態空間の土壌。一般システム理論＋カルマンフィルタで状態認識・予測・通知 |
| **STN** 状態遷移ネット | 構造（P＋T）。ペトリの原形を残し、物理界に開く |
| **発火ループ（VM）** | STN の実行機構。マーキング駆動の enabled→fire→loop。不変のペトリネット仮想マシン（ネット構造＝プログラム、ループ＝VM）（§3.2.1） |
| **PLAN** | 期待状態 Expected State(T) の正（業務定義 DB）。異常＝Expected≠Actual（§1.4） |
| **RBP** 境界言語 | トラスト形成エンジン。処理系から意味を排除＝「オート」。境界言語＝翻訳者 |
| **IF** 膜 | 感覚・運動。ポートの集合 |
| **SOS** 作動の運動器 | 記号界で実働できるシステムを操作するライブラリ |
| **接地** | 物理界をオペレータとして認知。未接地の系は真界（TrueWorld）ではない |
| **間接的開き** | STN は HUMOS を介してのみ物理界に開く |
| **能動ゲート** | 発火判定がライブマーキングを読む |
| **反射／審議** | 常態は反射（速い・局部）、例外のみ審議（遅い・中央経路） |
| **ドメインオブジェクト** | 状態の保持体（ネットではない）。圃場・コホート・実行者（§3.7） |
| **圃場** | 状態保持の代表例。状態＝保持中の期＋フェーズ（空／栽培中／片づけ未完了）。同期のみ保持 |
| **圃場状態ライフサイクル** | 空→第N期育苗(栽培中)→定植完了(片づけ未完了)→空。二値でなく中間状態を持つ |
| **ハイブリッド遷移** | STN のイベント駆動＋人間の確認駆動（Yes/No）で確定する圃場状態遷移 |
| **コホート** | 状態遷移のまとまり。3 層階層（第N期→圃場→トランジション） |
| **UI 階層解像** | コホートの表示は解像度で決める。トップは 1 階層子マクロ、深い階層は折り畳み |
| **要求トークン** | オブジェクト×スケジュール。要求種別ごとに属性のサブセットを運ぶ（防除要求は面積） |
| **防除（反復）** | 同じ episode の反復（毎回全 5 段）。1 マクロ＋トークンから N インスタンス生成 |
| **検鏡（連鎖）** | 異なる段の連鎖（検鏡1→…→検鏡N→定植）。圃場が内部状態から発生（内部状態遷移型） |
| **実働** | 状態遷移の作動（T の正体）。石3 リフレックスの役割名。人/機械/ロボット/SOS。登場ごとにドメイン登録（実行者） |
| **エージェント** | **廃止**（2026-09-14）。実働（実行者）で吸収（[真界_事業主体設計.md §2.1](真界_事業主体設計.md)） |
