# STB ドメイン STN 統合設計（固定 STN ＋ 5期の統合）

> 作成: 2026-09-11
> 対象: stn.html（STN・ライブ）のネット表示・ドロップダウン
> 前提: [真界_IF設計.md](真界_IF設計.md) §0.1（作動・実働・IF）・[TS設計.md §12.7](TS設計.md)（ナレッジ設計）

## 1. 問題

stn.html（STN・ライブ）のドロップダウンが **2 つの別ネット**を表示している:

| ドロップダウン項目 | 実体 | 内容 |
|---|---|---|
| **固定 STN** | `jobnet.NET`（ハードコード） | 防除/在庫確認の鎖（認知→評価→決定→処方→在庫チェック→作動） |
| **第5期** | `server._cohort_net(conn, 7)`（動的生成） | 検鏡/熱消毒/マルチ/定植の鎖 |

**本来は 1 つの「STB ドメインの STN」** である。2 つの別ネットとして表示されているのは誤り。

## 2. 概念モデル（ユーザー確認済み 2026-09-11）

### 2.1 固定 STN と 5期は 1 つ

「固定 STN」と「第5期」は**別物でなく 1 つ**。STB ドメインの STN は 1 つであり、
防除・在庫確認（現「固定 STN」）も検鏡・定植（現「第5期」）も**同じ STN のサブコホート**。

### 2.2 5段骨格は T の内部構造（トップレベルではない）

「認知→評価→決定→投射→作動」は **STN のトップレベル構造でなく、T（トランジション）の
内部構造**（[真界_IF設計.md §0.1](真界_IF設計.md)）。現「固定 STN」は 5段骨格を
トップレベル構造として表示しているが、これは修正済み（§0.1）の概念と矛盾する。
トップレベルは**サブコホート（検鏡/防除/在庫確認/定植）のネットワーク**である。

### 2.3 コホートの階層

```
STB ドメイン（ドメイン）
└── STB ドメインの STN（トップレベルコホート = 1 つのネット）
    ├── 検鏡（サブコホート）
    ├── 防除（サブコホート）
    ├── 在庫確認（サブコホート）
    └── 定植（サブコホート）
```

- **トップレベル** = STB ドメインの STN（サブコホートのネットワーク）
- **サブコホート** = 検鏡/防除/在庫確認/定植（各々がマクロノード）
- サブコホートにドリルダウンすると、その内部構造（5段骨格を含む）が見える

### 2.4 「5期」は収穫年（データ）であり、STN 構造ではない

- `cohorts` テーブル: `name='第5期'`, `period_no=5`, `harvest_year=2026`
- server.py:3490: `name = f"第{period_no}期"`（収穫年から自動生成）
- **翌年は「6期」になるが、STN 構造は同じ**（収穫年はデータ、構造ではない）
- 「5期」をネット名にすると、毎年の収穫年変更でネット名が変わる（無駄）
- **収穫年（5期/6期）は定植/検鏡サブコホートのデータ属性**であり、ネット名ではない

### 2.5 「固定」はプログラム構造の事実

「固定」は**意味レベルの概念でなく、プログラム構造の事実**（静的に定義された骨格）。
STN の構造は不変（5段骨格＋サブコホート構造）であり、データ（収穫年・圃場・薬剤）が
変わるだけ。だから「固定」と呼ぶが、これは「STB ドメインの STN」の別名に過ぎない。

## 3. ネット合成（設計）

### 3.1 トップレベルネット = STB ドメインの STN

トップレベルネットは**サブコホートのネットワーク**を表示する:

```
STB ドメインの STN（トップレベル）
┌─────────────────────────────────────────────────────────┐
│  [検鏡] ──▶ [定植]                                      │
│     │            │                                       │
│     │            ▼                                       │
│     │         [マルチ敷設]                               │
│     │            │                                       │
│     │            ▼                                       │
│     │         [熱消毒]                                   │
│     │                                                    │
│  [防除] ──▶ [在庫確認] ──▶ [作動:Slack]                  │
└─────────────────────────────────────────────────────────┘
```

- **マクロノード** = サブコホート（検鏡/防除/在庫確認/定植/マルチ敷設/熱消毒）
- **弧** = サブコホート間の接続（検鏡→定植、防除→在庫確認 等）
- マクロノードに**ドリルダウン**すると、その内部構造（5段骨格を含む）が見える

### 3.2 サブコホートの内部構造（ドリルダウン）

| サブコホート | 内部構造 | 現行の実体 |
|---|---|---|
| **防除** | 認知→評価→決定→処方→投射（5段骨格） | `jobnet.NET`（P_field→P_pest→P_input→P_vector→P_selection→P_rx→P_report） |
| **在庫確認** | 在庫チェック→在庫結果→作動 | `jobnet.NET`（P_inventory→P_inv_result→T_inventory_exec） |
| **検鏡** | 検鏡1→…→最終（順送り＋分化ありスキップ） | `_cohort_net`（P_judge{seq}→T_judge{seq}→T_ari{seq}→T_skip{seq}→T_force） |
| **定植** | 定植前（AND-JOIN）→定植完了 | `_cohort_net`（P_ready→T_transplant→P_transplant） |
| **マルチ敷設** | マルチ選定→在庫確認→敷設（3ジョブ） | `_cohort_net`（P_mulch_select→P_mulch_inv→T_multilay） |
| **熱消毒** | 熱消毒準備→熱消毒完了 | `_cohort_net`（P_heat_ready→P_heat_done→T_heat） |

### 3.3 収穫年（5期/6期）の扱い

- **収穫年はネット名でなく、定植/検鏡サブコホートのデータ属性**
- `cohorts` テーブルの `harvest_year`/`period_no` は**データ**（どの収穫年の育苗か）
- ネット名は「STB ドメインの STN」（収穫年に依存しない）
- 定植/検鏡サブコホートの表示に「（第5期・2026収穫）」を**データ属性として付与**する
  （ネット名ではなく、サブコホートのラベルに）

## 4. 命名

| 現行 | 修正後 | 理由 |
|---|---|---|
| **固定 STN**（ドロップダウン） | **STB ドメインの STN** | 「固定」はプログラム構造の事実、意味レベルでは「STB ドメインの STN」 |
| **第5期**（ドロップダウン） | **（削除）** | 収穫年はデータ属性、ネット名ではない。定植/検鏡サブコホートのラベルに付与 |
| ドロップダウン | **1 つのネット**（STB ドメインの STN） | 固定 STN と第5期は 1 つ |

## 5. 実装（設計）

### 5.1 server.py

- `_handle_net_get`（server.py:4110）:
  - 現行: `?cohort_id=N` → `_cohort_net` / 未指定 → `jobnet.net_to_json()`（2 つの別ネット）
  - 修正: **トップレベルネット**（サブコホートのネットワーク）を生成する
    - `jobnet.NET`（防除/在庫確認）と `_cohort_net`（検鏡/定植/マルチ/熱消毒）を
      **マクロノードとして統合**したネットを返す
  - サブコホートの内部構造は `?subcohort=<name>` でドリルダウン

### 5.2 stn.html

- ドロップダウン（stn.html:484）:
  - 現行: `<option value="">固定 STN</option>` ＋ cohorts から第5期
  - 修正: **1 つのネット**（STB ドメインの STN）を表示
  - サブコホートのドリルダウンは既存の `btnPetriBack`（← サブネットを閉じる）を流用
- ネット表示:
  - トップレベル = サブコホートのネットワーク（マクロノード＋弧）
  - マクロノードクリック = ドリルダウン（内部構造を表示）

### 5.3 収穫年の表示

- 定植/検鏡サブコホートのラベルに「（第5期・2026収穫）」をデータ属性として付与
- ネット名は「STB ドメインの STN」（収穫年に依存しない）

## 6. 検証

- トップレベルネットがサブコホートのネットワークを表示すること
- サブコホートのドリルダウンが内部構造（5段骨格を含む）を表示すること
- 収穫年（5期/6期）がネット名でなくデータ属性として表示されること
- 既存の固定 STN（防除/在庫確認）・第5期（検鏡/定植）の表示が壊れないこと

## 7. 残（本設計の範囲外）

- サブコホート間の**共有プレース**（検鏡→定植の timing_token 等の接続）の精緻化
- マクロノードの**階層表示**（2 階層以上のドリルダウン）
- 収穫年（6期）の**データ登録**（来年の育苗バッチ登録）
